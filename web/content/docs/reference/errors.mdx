A refused write still reaches consensus: validators agree the refusal is the right result, and the transaction reads ACCEPTED. The site counts a write as done only when the status is ACCEPTED or FINALIZED **and** the execution returned; otherwise it shows the sentence below, which the transaction carries in its result payload. A refused write changes nothing, and value sent with it stays with the sender.

`[EXPECTED]` refusals are deterministic and identical on every validator. `[LLM_ERROR]` means a model answer could not be used: not JSON, a label outside the four, or a duplicate id the judge was not shown. Validators then disagree on purpose, so the round rotates to a committee that can answer, and nothing defaults to a verdict.
